# Bookstore schema

Written by: human
Target audience: human, AI agent

This file describes the schema of a fictional bookstore. It describes the entities and relationships between the entities in natural language. It is intended as the input to create a LinkML schema. The schema should reside in schema/bookstore.yaml.

The schema metadata must be:

- id: https://example.org/bookstore
- name: bookstore
- title: Bookstore schema
- description: Schema for a fictional bookstore, including entities and their relationships.
- default_prefix: bookstore
- default_range: string
- prefixes:
  - bookstore: https://example.org/bookstore/
  - linkml: https://w3id.org/linkml/
- imports: linkml:types

All slots are required unless explicitly marked optional below. A slot without a `required` declaration should be treated as optional only when this description says it is optional.

Model and Person are non-addressable base classes. Book, Author, Publisher, User, and Review are addressable classes and must have an `api_resource_name` annotation. Addressable classes should inherit from Model directly or indirectly.

Classes may have uniqueness constraints. These are detailed in the slot descriptions but should apply to the class's unique_keys property.

## Annotations

The schema uses the following annotations for classes:

- api_resource_name - the lowercase plural version of the entity name (Book -> books)

And the following annotations for slots:

- write_model: boolean - does this slot exist in the request sent to the API?
- read_model: boolean - does this slot exist in the response from the API?

Relationships should not appear in the read or write models. They must have `read_model: false` and `write_model: false`.

The `id` slot is an identifier with range `string`, is required, and has `write_model: false` and `read_model: true`.

The `created_at` slot has range `datetime`, is optional, and has `write_model: false` and `read_model: true`.

## Entities

### Model

The base model for this project. Any addressable model should have is_a: Model.

#### Model slots

- id - a UUID string generated by the service. It is an identifier, is required, and is present in the read_model but not the write_model.
- created_at - an ISO-formatted UTC datetime of when the entity was created in the system. This is an infrastructure slot recorded in the database, but it is optional, not set in the write model, but is revealed in the read model.

### Person

The base class of a human being.

### Person slots

- name
- gender - optional
- date_of_birth - an ISO-formatted date of when this human was born, optional

### Book

A book sold by the bookstore.

### Book slots

- title - a required string present in both the write_model and read_model. It must be unique within Book. Add a `unique_keys` entry named `unique_title` containing `title`.
- ISBN - a required string containing exactly 13 ASCII digits. Use the pattern `^[0-9]{13}$`. It must be present in both the write_model and read_model. It must be unique within Book. Add a `unique_keys` entry named `unique_isbn` containing `ISBN`.
- authors - a non-empty collection of authors of the book. It has range `Author`, is multivalued, and has minimum cardinality 1. It must not appear in either API model.
- publisher - an optional single-valued reference with range `Publisher`. It must not appear in either API model.
- genre - a required value from the `Genre` enumeration, present in both the write_model and read_model:
  - Sci-fi
  - Fantasy
  - Crime
  - Thriller
  - Non-fiction
  - Biography
- reviews - a 0-n collection of Review entities which have been submitted for this book. It has range `Review`, is multivalued, and has minimum cardinality 0. It must not appear in either API model.

### Author

A human who has authored books sold by the bookstore. is_a Person.

#### Author slots

- books_published - a 0-n collection of books which this author has written. It has range `Book`, is multivalued, and has minimum cardinality 0. It must not appear in either API model.

### Publisher

An organization who publishes books sold by the bookstore

#### Publisher slots

- name - a required string present in both the write_model and read_model

### User

A customer of the bookstore. is_a Person.

#### User slots

- has_bought - a 0-n collection of books which this user has bought. It has range `Book`, is multivalued, and has minimum cardinality 0. It must not appear in either API model.
- reviews - a 0-n collection of reviews the user has submitted. It has range `Review`, is multivalued, and has minimum cardinality 0. It must not appear in either API model.

### Review

User-submitted reviews of books in the store.

#### Review slots

- user - the required user who authored the review. It has range `User`, is single-valued, and appears in the write model but not the read model.
- score - a required integer rating between 0 and 5 stars, inclusive. It appears in both the write and read models.
- review_text - an optional string containing the user's review of the book. It appears in both the write and read models.
